# PROJECT REQUIREMENTS
## Part 1 – Introduction, Project Goals & Scope

---

# 1. Introduction

## 1.1 Project Name

**English Teacher Gamification Platform**

---

## 1.2 Purpose

The English Teacher Gamification Platform is a lightweight, modern web application designed specifically for English language teachers who manage multiple student groups.

The primary objective of this platform is to replace traditional spreadsheet-based classroom management systems (such as Google Sheets) with an integrated, interactive, and gamified web application.

The platform will enable teachers to efficiently manage attendance, homework, payments, rankings, achievements, reports, and long-term student progress while significantly reducing administrative workload.

The application must prioritize speed, simplicity, stability, and user experience above all other aspects.

---

# 2. Vision

The long-term vision of this project is to create a professional classroom management system that combines the flexibility of Google Sheets with the convenience of modern Learning Management Systems (LMS) and the motivational aspects of gamification.

Instead of manually maintaining spreadsheets every lesson, teachers should be able to manage an entire class using a fast and intuitive interface that requires only a few clicks.

The application should encourage student motivation through points, levels, badges, achievements, rankings, streaks, and rewards while simultaneously providing teachers with meaningful analytics and reports.

---

# 3. Project Objectives

The project aims to achieve the following objectives.

## 3.1 Replace Google Sheets

The application must completely replace the teacher's current Google Sheets workflow.

Every feature currently performed manually inside spreadsheets should be available inside the application.

---

## 3.2 Improve Teacher Productivity

Teachers should spend less time managing administrative tasks and more time teaching.

Routine classroom operations such as attendance, homework evaluation, payment tracking, and report generation must require as few interactions as possible.

---

## 3.3 Increase Student Motivation

The platform should motivate students through a balanced gamification system.

Students should receive rewards for positive behavior such as:

- Regular attendance
- Homework completion
- Perfect homework
- Consistent participation
- On-time payment
- Long attendance streaks
- Monthly achievements
- Special events
- Birthday rewards

Students should also lose points for negative behaviors according to configurable rules.

---

## 3.4 Long-Term Progress Tracking

The system must permanently store historical information for every student.

Teachers should be able to analyze student performance over weeks, months, and years.

Historical data must never be lost.

---

## 3.5 Automation

The platform should automate repetitive tasks wherever possible.

Examples include:

- Automatic point calculation
- Automatic ranking updates
- Automatic badge assignment
- Automatic level progression
- Automatic certificate generation
- Automatic weekly reports
- Automatic monthly reports
- Automatic statistics updates
- Automatic achievement tracking

---

## 3.6 Data Reliability

The application must protect teacher data.

Automatic backups, validation, and recovery mechanisms should prevent accidental data loss.

---

# 4. Target Users

This application is designed primarily for English language teachers.

Expected users include:

- English Teachers
- IELTS Teachers
- Language Center Teachers
- Private Tutors

The initial version targets individual teachers rather than entire educational institutions.

# 2.1 Authentication Module

## Purpose

The Authentication Module is responsible for securely identifying teachers, protecting application data, and ensuring that each teacher can access only their own information.

Students do not have accounts.

Only teachers are authenticated.

---

# 2.2 User Registration

The system shall allow new teachers to create an account.

Registration requires the following information:

- Full Name
- Email Address
- Password
- Confirm Password

Passwords must satisfy the following rules:

- Minimum 8 characters
- At least one uppercase letter
- At least one lowercase letter
- At least one number

Password strength should be displayed while typing.

---

# 2.3 Email Validation

The system shall verify that the email address is unique.

Duplicate accounts using the same email address shall not be allowed.

The system shall validate email format before submission.

---

# 2.4 Email Verification

After registration, the system shall send an email verification link.

The teacher shall verify the email before using the application.

Unverified accounts shall have restricted access.

---

# 2.5 Login

Teachers shall log in using:

- Email
- Password

The login page shall include:

- Remember Me
- Forgot Password
- Show Password
- Language Switch
- Theme Switch

Successful login redirects directly to the Dashboard.

---

# 2.6 Session Persistence

The system shall automatically keep teachers logged in unless they explicitly log out.

Teachers shall not need to log in every time they reopen the website.

Session expiration shall occur securely.

---

# 2.7 Logout

Teachers shall be able to log out from any page.

Logging out shall immediately invalidate the active session.

All protected pages shall become inaccessible until the teacher logs in again.

---

# 2.8 Forgot Password

Teachers shall be able to reset forgotten passwords.

Password reset process:

1. Enter registered email.
2. Receive reset email.
3. Open secure link.
4. Create new password.
5. Login again.

Reset links shall expire automatically after a secure time period.

---

# 2.9 Change Password

Authenticated teachers shall be able to change passwords.

Required fields:

- Current Password
- New Password
- Confirm New Password

Current password must be verified before saving.

---

# 2.10 Teacher Profile

Every teacher shall have a personal profile.

Profile includes:

- Full Name
- Email
- Preferred Language
- Theme
- Account Creation Date
- Last Login
- Total Groups
- Total Students

Teachers may edit their profile information.

---

# 2.11 Language Preferences

The application shall support:

- Uzbek
- English

Teachers may switch language at any time.

Language preference shall be saved automatically.

---

# 2.12 Theme Preferences

Supported themes:

- Light
- Dark

Teachers may switch themes instantly.

Selected theme shall remain after logout.

---

# 2.13 Teacher Settings

Each teacher shall have independent settings.

Examples:

- Attendance Rules
- Homework Rules
- Payment Rules
- Notification Preferences
- Sound Settings
- Animation Settings
- Certificate Templates

Settings shall never affect other teachers.

---

# 2.14 Data Isolation

Every teacher shall have completely isolated data.

Teachers can access only:

- Their Groups
- Their Students
- Their Homework
- Their Reports
- Their Analytics
- Their Certificates
- Their Teacher Notes

Cross-account access shall never be permitted.

---

# 2.15 Security Requirements

Passwords shall never be stored in plain text.

Authentication shall use Supabase Authentication.

Database access shall be protected using Row Level Security (RLS).

Every API request shall verify the authenticated teacher.

---

# 2.16 Unauthorized Access

If an unauthenticated user attempts to access protected pages, the system shall redirect them to the Login page.

Unauthorized API requests shall return appropriate HTTP status codes.

---

# 2.17 Multiple Devices

Teachers shall be allowed to access their account from multiple devices.

Data synchronization shall occur automatically.

---

# 2.18 Last Login

The system shall record:

- Last Login Date
- Last Login Time

This information shall be visible in the teacher profile.

---

# 2.19 Account Deletion

Teachers may permanently delete their account.

Before deletion, the system shall display a confirmation dialog explaining that all associated data will be permanently removed.

Deletion shall require password confirmation.

---

# 2.45 Edge Cases & Exception Handling

The system shall gracefully handle unexpected situations without data loss or application crashes.

## Empty Groups

If a teacher creates a group without students:

- The group shall still be created successfully.
- The Journal shall display an empty state.
- The teacher shall be prompted to add students.
- Dashboard statistics shall treat the group as having zero students.

---

## Duplicate Student Import

If duplicate students are detected during import:

The system shall display all detected duplicates.

The teacher shall choose one of the following actions:

- Skip Duplicate
- Replace Existing Record
- Merge Records
- Import Anyway

No duplicate shall be imported automatically without teacher confirmation.

---

## Invalid Spreadsheet Data

If imported spreadsheet data contains invalid values:

Examples:

- Missing student name
- Invalid phone number
- Empty payment number
- Unsupported columns

The system shall:

- Highlight invalid rows.
- Explain validation errors.
- Import only valid rows if requested.
- Never crash during import.

---

## Internet Connection Lost

If the internet connection is interrupted while the teacher is working:

- Unsaved actions shall be stored locally.
- The interface shall notify the teacher.
- Synchronization shall begin automatically once the connection is restored.
- No attendance, homework, or payment records shall be lost.

---

## Browser Refresh

If the browser is refreshed unexpectedly:

- The teacher session shall remain active.
- Unsaved draft changes shall be restored whenever possible.

---

## Accidental Group Deletion

Deleting a group shall require:

- Confirmation dialog
- Warning message
- Password confirmation (optional)
- Final confirmation button

Deletion shall never occur accidentally.

---

## Monthly Journal Creation Failure

If automatic journal generation fails:

- The teacher shall receive a notification.
- Existing monthly data shall remain untouched.
- The teacher shall be able to regenerate the journal manually.

---

## Large Groups

Groups containing large numbers of students shall remain responsive.

The application shall use:

- Pagination when appropriate.
- Virtual scrolling.
- Lazy rendering.

---

## Empty Dashboard

If the teacher has no groups:

The Dashboard shall display:

- Friendly illustration
- "Create Your First Group" button
- Quick setup instructions

---

## Archive Failure

If archive generation fails:

- Current data shall remain unchanged.
- No historical records shall be deleted.
- The archive operation shall be retryable.

---

## Security Violations

If a teacher attempts to access another teacher's group:

The system shall:

- Deny access.
- Return an authorization error.
- Record the event in the activity log.

---

## System Stability

Under all edge cases:

- The application shall never crash.
- Existing data shall never become corrupted.
- Teachers shall always receive meaningful error messages.
- Recovery shall be possible whenever technically feasible.
